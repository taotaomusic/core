# 动效与渲染性能优化计划

本目录记录 2026-08-24 对桃桃音乐 Android 端完成的动效审计与执行方案。方案遵循项目现有 `AnimationTheme.kt` 集中式规范，并优先保证播放页与歌词页的帧稳定性。

001–004 属于动效与渲染优化；005 起为架构与音源接入类方案，007 为设计系统与组件库选型，008 为传输层加密，沿用同一套编号与状态约定。

| 编号 | 方案 | 严重度 | 状态 | 依赖 |
| --- | --- | --- | --- | --- |
| 001 | 隔离歌词帧级状态 | 高 | DONE | 无 |
| 002 | 收紧页面层级与高频导航动效 | 高 | DONE | 无 |
| 003 | 精简高频控件与搜索结果动效 | 中 | DONE | 002 的动效 token |
| 004 | 补齐状态过渡与无障碍语义 | 中 | DONE | 001、002 |
| 005 | 客户端业务模块化迁移 | 高 | TODO | 无 |
| 006 | 接入酷我「波点」音源 | 中 | TODO | 005 不阻塞，但需先抽音源分派 |
| 007 | Android 设计系统与组件库选型 | 中高 | 阶段 1 DONE（已建截图验证链路） | 阶段 0 需先升工具链；阶段 2 建议排在 005 之后 |
| 008 | 全局传输层加密（Rust 多目标） | 高 | 模块 DONE（未接入链路） | 无。不阻塞也不被 005/006/007 阻塞 |

推荐顺序为 001 → 002 → 003 → 004：先消除逐帧重组压力，再统一页面运动语言，之后收紧高频控件，最后完善较少使用的状态切换和辅助功能体验。

## 执行结果

- 歌词帧级播放位置仅由当前逐字行读取；非当前行不再随每帧重组，且所有歌词行保持相同高度。
- “音乐 / 我的”、播放 / 暂停、搜索结果列表等高频路径改为即时响应；详情与面板等低频层级路径保留短促的 transform/opacity 过渡。
- 搜索异步状态使用 Android Compose 语义树的 `liveRegion`，歌词跳转动作提供明确标签；Compose 动效继续跟随系统动画时长设置。
- 每次 Release 都以 `output-metadata.json` 为唯一版本来源，并在签名校验后交付 APK。

## 007 阶段 1 执行结果

- 在 `player-ui` 建立四套 token：排版（10 档字号）、形状（5 档圆角）、间距（8 档 4dp 基数）、层次（4 级）。
- `TaotaoPlayerTheme` 不再使用 Material 默认排版与形状；`AppleStyleTheme` 降级为 `@Deprecated` 别名。
- `player-ui/commonMain` 的硬编码字号与圆角字面量清零；新增 10 个 token 结构测试（共 15 项全绿）。
- 三端（Android / Windows / Web）编译通过。
- **建立了视觉验证链路**：`webApp` 与安卓共用 `player-ui`，对 Web 端截图可验证共享组件。
  据此发现并修掉了 `PlayerArtworkSlot` 的**封面方块鬼影**（改动前就存在的形状不匹配），
  以及 `webApp` 绕过 `TaotaoTypography` 导致的三端排版分叉。
  对照截图在 `artifacts/design-system-tokens/`。
- **安卓真机仍未验证**（截图链路覆盖不到安卓专属 Material 控件），
  另有 4 项有视觉 delta 的改动需要人工确认，详见方案文档的「尚未验证」一节。
