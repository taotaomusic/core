# 安全设计与威胁边界

## 当前方案

版本 3 使用以下组合：

1. 主密钥必须是 256 位随机值。
2. 每条消息生成 128 位随机盐，并在其后 64 位混入进程内原子单调序列。
3. HKDF-SHA256 以主密钥、加固后的盐和固定域分离字符串派生独立消息子密钥。
4. AES-256-GCM-SIV 使用独立子密钥和 96 位随机 nonce 完成加密与认证。
5. 密文头携带 Unix 毫秒签发时间，格式头和调用方提供的 AAD 一起参与认证。
6. 消息子密钥离开作用域时使用 `OPENSSL_cleanse` 清除。
7. 主密钥保存在单独堆对象中，并尝试使用 `VirtualLock` 或 `mlock` 防止换页；调用方可用 `isKeyMemoryLocked()` 检查结果并选择启动失败。
8. 固定头 `tao` 与固定尾 `yuan` 都参与 AEAD 认证；它们是公开协议标识，不作为秘密或密码学强度来源。
9. 可选压缩使用每消息独立的 Zstandard level 1，只有结果更小时才采用；压缩标志和原始长度都参与认证。

GCM-SIV 对 nonce 意外复用具有更好的容错能力，但这不是复用 nonce 或密钥的许可。随机盐与消息子密钥进一步隔离了不同消息。原子序列不会替代 CSPRNG：它只保证同一进程生命周期内，即使随机源错误地重复返回相同盐，盐仍不重复。它不能跨进程或重启提供全局唯一保证；要求这种保证时，上层必须提供持久化、原子递增的消息序号，并通过 AAD 绑定。

## 容器解析

解析器不搜索 `tao`，只接受偏移 0 的固定头，并把输入的最后 4 字节严格视为 `yuan`。密文段长度由容器总长度减去固定开销得到；`originalSize` 只表示解压后的明文长度，不能用于定位密文尾部。前置字节、尾随字节以及“垃圾 + 第二个 yuan”都会被拒绝或在 AEAD 认证时失败。所有未认证结构错误统一为“密文容器无效”，接口层还必须把结构、认证、过期和重放拒绝映射为同一种外部响应。

## 压缩侧信道

压缩发生在加密之前，因此密文总长度会反映压缩结果。若同一明文同时含有秘密值和攻击者可以反复控制、猜测的内容，攻击者可能通过长度变化逐步猜出秘密，这属于 CRIME/BREACH 类压缩侧信道。

因此：

- 压缩必须由调用方显式选择，默认关闭；
- AAD 永不压缩；
- 每条消息使用全新的 Zstandard 上下文，不跨请求复用字典或历史窗口；
- 身份令牌、Cookie、验证码、API Key 等秘密不得与攻击者输入共同压缩；
- 无法证明数据边界安全时使用 `CompressionMode::Disabled`；
- 解密端先完成 AEAD 认证，再按受认证的原始长度解压；原始长度超过上限、帧长度未知或不一致都会拒绝。

压缩能减少网络字节和大消息传输耗电，但会增加少量 CPU 消耗。模块采用 Zstandard level 1，并仅保留真正变小的结果，以在延迟、耗电和体积之间取平衡。

## 防重放

AEAD 只能证明消息真实且未被修改，不能阻止攻击者重复发送同一条合法密文。需要防重放的入口必须调用 `decryptOnce`，不能直接调用 `decrypt`。

`decryptOnce` 的顺序固定为：

1. 对公开但未认证的签发时间作廉价预筛；该结果只能用于拒绝，不能证明消息可信；
2. 完整认证并解密；
3. 再次校验已经受认证的签发时间没有超过 `maximumAge`，也没有超出允许的未来时钟偏差；
4. 计算绑定 AAD 和完整密文的 SHA-256 Replay ID；
5. 以服务端接收时间为基准，用 `maximumAge + allowedFutureSkew` 调用 `ReplayStore::consume` 原子登记；
6. 只有首次登记成功才返回明文。

模块自带的 `InMemoryReplayStore` 只覆盖单进程生命周期。多实例或重启后仍需防重放时，必须实现持久化 `ReplayStore`：

- PostgreSQL：以 Replay ID 为唯一键执行 `INSERT ... ON CONFLICT DO NOTHING`，并保存过期时间；
- Redis：使用 `SET key value NX PX <毫秒>`；
- 不允许使用“先查再写”，否则并发请求会同时通过。

数据库的 `expires_at` 必须由服务端当前时间加 `maximumAge + allowedFutureSkew` 得到，不能由客户端提供的 `issuedAtMs` 推导。

缓存容量满时内存实现采用失败关闭策略：拒绝新消息，不提前驱逐尚未过期的 ID。接口层还应限制请求体大小和请求频率，避免合法认证消息耗尽容量。

## 侧信道缓解

- 认证标签比较由 OpenSSL GCM-SIV 实现中的 `CRYPTO_memcmp` 完成，避免按首个错误字节提前退出。
- 模块不自行实现 AES、POLYVAL、HKDF 或随机数生成。
- 认证失败统一为同一路径，不向调用方暴露标签错误位置。
- 主密钥和派生子密钥都会显式清除；主密钥尽力锁定在内存中。
- Windows/MSVC 启用栈保护、控制流保护、DEP 和 ASLR；MinGW 启用强栈保护、FORTIFY、DEP、ASLR 和高熵地址。
- `kiwi_crypto_side_channel_test` 随机交错测量认证标签首字节错误与末字节错误，以 Welch t 检查明显的时序回归。
- cipher/KDF 算法描述符在进程内缓存，消息上下文保持独立，减少重复 provider 查询带来的延迟和耗电。
- 默认明文与 AAD 上限阻止超大输入制造无界内存和 CPU 消耗。

这个时序测试只能发现明显的软件提前退出，不能证明不存在侧信道。以下威胁不在本模块可独立解决的范围内：

- 物理功耗、电磁和故障注入；
- Spectre、Meltdown 等微架构攻击；
- 已取得管理员、调试器或进程读权限的攻击者；
- OpenSSL、编译器、CPU 固件或操作系统自身漏洞；
- 调用方日志、崩溃转储、遥测或序列化代码泄露密钥/明文。

高价值密钥应存放在 HSM、TPM、云 KMS 或独立密钥服务中，由密钥句柄执行加解密，而不是把长期主密钥加载到业务进程。

## 上线检查清单

- 使用 CSPRNG 生成 32 字节主密钥，不使用人类口令或示例密钥。
- 生产环境检查 `isKeyMemoryLocked()`，按威胁模型决定失败时是否拒绝启动。
- 每类接口使用稳定且不同的 AAD，至少包含协议版本、HTTP 方法和规范化路由。
- 一次性请求只调用 `decryptOnce`，并为多实例配置持久化原子 `ReplayStore`。
- Replay ID 有效期覆盖服务允许的最大时钟偏差和请求生命周期。
- 接口有请求体上限、速率限制、超时和统一错误响应。
- 禁止记录密钥、明文、完整密文、认证标签或 OpenSSL 内部错误栈。
- CI 运行普通测试及带 `security` 标签的侧信道烟雾测试。
- 定期升级 OpenSSL，并重新执行静态库、DLL 和安装包消费测试。
